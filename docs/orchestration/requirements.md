# 세라프 개발 오케스트레이션 요구사항

> 상태: 인터뷰 진행 중
> 최종 구현 승인 전에는 제품 코드와 실행 설정을 변경하지 않는다.

## 확정된 결정

### 사용자와 목적

- 주 사용자는 세라프 저장소를 개발하는 프로젝트 소유자다.
- 일반 세라프 앱 사용자를 위한 제품 기능이 아니라, 저장소 개발 작업을 돕는 오케스트레이터를 설계한다.

### 첫 번째 완성 범위

- 자연어 개발 요청을 해석한다.
- 관련 코드와 문서를 조사한다.
- 근거와 함께 변경 계획을 제안한다.
- 사용자가 계획을 승인한 뒤 코드를 변경한다.
- 변경에 맞는 검사와 빌드를 실행하고 결과를 보고한다.

### 승인 경계

- 조사와 읽기 전용 분석은 승인 전에 수행할 수 있다.
- 코드·설정 등 프로젝트 파일 변경은 계획 승인 후에만 수행한다.
- 구현 승인 전에는 프레임워크나 모델 구성을 확정하지 않는다.

### 실행 진입점

- 첫 버전은 현재 로그인된 공식 Codex의 대화와 프로젝트 명령을 주 진입점으로 사용한다.
- 별도 터미널 독립 실행기는 첫 버전의 필수 범위가 아니다.

### 작업 수명주기

- 승인된 계획 한 건을 구현하고 해당 계획의 검증을 마친 뒤 종료한다.
- 여러 작업을 자동으로 이어서 실행하거나 무제한으로 보수 반복하지 않는다.

### 모델 전달 범위

- 작업에 필요한 코드와 프로젝트 문서의 최소 구간을 공식 Codex 모델에 전달할 수 있다.
- `.env`, 인증 키, 빌드 산출물, 로컬 원본 PDF와 평가용 정답은 기본 전달 범위에서 제외한다.
- 제외 자료가 꼭 필요한 작업은 별도의 명시적 결정 없이는 전달하지 않는다.

### 실행 기록

- 각 작업의 계획, 명시적 승인, 변경 결과와 검증 증거를 실행별 Markdown 문서로 남긴다.
- 실행 기록은 `docs/orchestration/runs/` 아래에서 추적할 수 있어야 한다.

### 범위 변경

- 승인된 목적을 구현하는 데 직접 필요한 테스트와 개발 문서 변경은 승인 범위에 포함할 수 있다.
- 새로운 기능 영역이나 별도 제품 동작으로 수정 범위가 확장되면 구현을 멈추고 재승인을 요청한다.

### 보수 한도

- 승인된 구현의 검증 실패는 같은 원인에 대해 최대 두 번까지 집중 보수한다.
- 두 번의 보수 후에도 실패하면 추가 변경 없이 실패 증거와 남은 문제를 보고한다.

## 저장소에서 확인된 사실

- 클라이언트는 Expo Web과 React Native가 코드를 공유한다.
- 백엔드는 Express 5, PostgreSQL 17, pgvector 기반이다.
- PDF 적재, 구조화, 청킹, Gemini 임베딩, 하이브리드 검색과 근거 기반 답변이 구현돼 있다.
- 프로젝트에는 Oh My Codex 역할 정의와 Codex hook 기능 설정이 존재한다.
- 세라프 전용 개발 오케스트레이터와 LangChain/LangGraph 의존성은 없다.
- 일부 아키텍처·RAG 문서는 실제 Gemini 구현보다 오래된 OpenAI 구성을 설명한다.

## 미결정 사항

- Codex CLI 로그인 사용 방식과 로그인 불가 시 동작
- 문서 조회 예산, 캐시와 변경 감지 정책
- 역할 분리 수준과 LangChain/LangGraph 도입 필요성
- 실행 기록 문서의 세부 스키마와 파일명
