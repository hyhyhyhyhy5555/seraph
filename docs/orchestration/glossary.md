# 세라프 개발 오케스트레이션 용어집

> 상태: 인터뷰와 함께 갱신

## 오케스트레이터

사용자의 개발 요청을 해석하고 조사, 계획, 승인 대기, 구현, 검증과 결과 취합의 흐름을 관리하는 주 실행 계층이다.

## 개발 작업

세라프 저장소의 코드, 설정 또는 개발 문서를 조사하거나 변경하고 검증하는 요청이다.

## 계획 승인

오케스트레이터가 변경 목적, 근거, 대상 파일, 위험과 검증 방법을 제시한 뒤 프로젝트 소유자가 구현을 허용하는 명시적 결정이다.

## 읽기 전용 조사

파일 검색, 필요한 구간 조회, 현재 설정 확인과 변경 없는 검사를 포함한다. 프로젝트 파일의 내용이나 외부 시스템 상태를 변경하지 않는다.

## 제품 파일

앱·백엔드 코드, 데이터베이스 마이그레이션, 실행 설정과 배포 설정처럼 제품 동작에 영향을 주는 저장소 파일이다.

## Codex hook

Codex 실행 흐름 안에서 특정 이벤트에 반응하는 확장 지점이다. 독립 실행기의 정책과 동일한 것으로 간주하지 않는다.

## 독립 실행기

Codex 대화 밖에서도 명령으로 시작할 수 있는 프로젝트 전용 실행 프로그램이다. 첫 버전의 필수 범위에서는 제외됐다.

## 최소 구간 전달

모델이 작업을 수행하는 데 필요한 파일 전체가 아니라 관련 심볼, 문단, 페이지 또는 표 범위만 선택해 전달하는 정책이다.

## 제외 자료

기본 모델 전달 범위에서 제외되는 `.env`, 인증 키, 빌드 산출물, 로컬 원본 PDF와 평가용 정답을 뜻한다.

## 근거

계획, 변경 또는 답변을 뒷받침하는 저장소 파일·심볼·문서 구간·검사 결과다.

## 실행 기록

개별 작업의 요청, 조사 근거, 승인된 계획, 변경 범위, 보수 횟수와 검증 결과를 담는 Markdown 문서다.

## 집중 보수

승인된 목표와 같은 실패 원인 안에서 수행하는 제한된 후속 수정이다. 새로운 기능이나 별도 문제 해결은 포함하지 않는다.

## 범위 확대

승인된 목적을 넘어 새로운 기능 영역, 제품 동작 또는 독립적인 변경 대상을 추가하는 것이다. 발견 시 재승인이 필요하다.
