# 01. Windows와 Ubuntu 가상머신

## 목표와 사전 조건

목표는 윈도우에서 독립된 Linux 서버에 SSH 접속하고 재부팅 후 복구되는 것이다. 사용자 화면에서 i5-1240P·RAM 16GB·Iris Xe·저장 공간 여유 약 39GB를 확인했다. Windows 에디션은 아직 보이지 않으므로 VM 도구 선택은 보류 상태다.

가상화 기능을 켜기 전 중요한 개인 파일을 백업한다. BIOS 변경 시 장치 암호화 복구 키를 확인한다. 호스트 전체를 다시 설치하는 작업은 필요하지 않다.

## 1. 호스트 정보 수집

Windows PowerShell:

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber, CsTotalPhysicalMemory
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors, VirtualizationFirmwareEnabled
Get-Volume | Select-Object DriveLetter, FileSystemLabel, SizeRemaining, Size
systeminfo
```

작업 관리자 → 성능 → CPU에서 가상화 상태를 확인한다. 비활성화라면 PC 제조사 안내에 따라 UEFI의 Intel VT-x 또는 AMD-V/SVM을 켠다. 명령 출력에 호스트 이름·네트워크 정보가 포함될 수 있으므로 공유할 때 필요한 항목만 전달한다.

## 2. VM 도구 결정

- Windows Pro/Enterprise 등 Hyper-V 지원 에디션: Hyper-V 우선 검토.
- Home: Hyper-V 역할을 설치할 수 없다. 지원되는 다른 하이퍼바이저를 선택한 뒤 네트워크 절차를 맞춘다.
- WSL2는 개발 보조로 쓸 수 있지만, 이번 실습의 주 서버는 명시적인 Linux VM으로 둔다.
- Hyper-V, 다른 하이퍼바이저, Android 에뮬레이터를 함께 사용하면 가속 호환성·메모리 압박이 생길 수 있다. 처음에는 실제 Android폰을 사용한다.

Hyper-V 지원 에디션으로 확정한 경우에만 관리자 PowerShell:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
```

재부팅이 필요하면 진행 중인 작업을 저장한 뒤 한다. Home에서 이 명령으로 지원 제한을 우회하려 하지 않는다.

## 3. 자원 예산 잡기

사용자 제공 사양에 맞춘 **초기 제안**이다. 실제 Windows 유휴 메모리·부하를 측정한 뒤 조정한다. 성능을 보장하는 수치는 아니다.

| 항목 | 시작 설정 | 운영 방식 |
| --- | --- | --- |
| Linux VM 수 | 1대 | K3s 단일 노드, API·DB부터 실행 |
| VM vCPU | 4 | API·DB·AI batch 동시성 제한, 빌드는 맥북 |
| VM RAM | 고정 6GB | Windows 자체 사용량과 운영 도구 여유 확보 |
| VM 가상 디스크 | 초기 최대 60GB 제안 | 실제 호스트 여유 공간 확보 후 생성 |
| GPU | CPU 경로로 시작 | Iris Xe 전달·가속을 전제하지 않음 |
| Android 테스트 | 맥북·실제 기기 | 그램에서 에뮬레이터·Android 빌드를 실행하지 않음 |
| Git·Registry·배포 러너 | 기본 서비스 검증 뒤 순차 추가 | 빌드 러너는 맥북, 그램 도구 VM 증설은 실측 후 |

### 현재 가장 먼저 해결할 문제: 저장 공간

화면상 총 238GB 중 199GB를 사용해 약 39GB가 남아 있다. OS·실행 이미지 layer·DB·모델·로그·Registry가 증가하므로 현재 여유만으로 전체 운영을 안정적으로 유지하기는 어렵다. npm/Gradle·Android SDK 빌드 공간은 맥북에서 별도 관리한다.

1. Windows 설정 → 시스템 → 저장소에서 사용량을 분류한다.
2. 불필요한 앱·정리 가능한 임시 파일·옮길 수 있는 개인 파일을 사용자가 검토한다. 개인 파일이나 다른 프로젝트를 자동 삭제하지 않는다.
3. `Get-Volume`으로 다른 드라이브의 실제 여유 공간도 확인한다. 이 화면만으로 디스크 종류나 물리 디스크 개수를 단정하지 않는다.
4. **서비스 VM 단계는 호스트 여유 80~100GB 확보를 설계 목표**로 잡는다. 이는 이 실습용 예산이며 K3s 공식 최소 용량은 아니다.
5. 그램에 Android SDK·Gradle cache를 설치하지 않는다. Git·Registry·모델·DB 사용량이 늘면 실측 후 추가 저장 공간을 검토한다. 맥북의 빌드 여유 공간은 별도로 확인한다.
6. 먼저 파일 정리로 확보 가능한지 확인하고, 부족하면 추가/외장 저장 장치 선택을 별도 결정한다.
7. 동적 확장 가상 디스크가 처음 작게 보이더라도 최대치만큼 물리 공간이 예약된 것은 아니다. host와 guest 여유를 함께 감시한다.

### 이 장비에서의 확장 순서

K3s+API+소량 DB → 작은 CPU 임베딩 모델 → Git·Registry·모니터링 순서다. 빌드는 모두 맥북에서 하고 그램에는 결과물만 전달한다. 작은 임베딩도 지연·RAM을 측정하며 대형 생성 LLM·여러 상시 VM·전체 모니터링 스택의 동시 실행을 초기 목표로 삼지 않는다.

그램에는 필요한 경우 namespace 권한이 제한된 배포 runner만 둔다. 이 runner에서는 npm·Gradle·Docker build를 실행하지 않으며, 전달된 이미지 digest 배포·migration Job·상태 검사만 처리한다.

## 4. Ubuntu VM 생성

1. 지원 중인 Ubuntu Server LTS 이미지를 공식 사이트에서 다운로드한다.
2. 이미지 checksum을 확인하고 선택한 버전을 작업 기록에 적는다.
3. Hyper-V라면 2세대 VM을 만들고 Ubuntu용 보안 부팅 템플릿을 확인한다.
4. 서비스 VM에는 예측 가능한 메모리를 배정한다. 동적 메모리를 사용하면 DB·K3s 부하 중 메모리 변동을 관찰한다.
5. OS 디스크와 DB 데이터용 가상 디스크를 분리할지 결정한다. 분리는 관리 편의이며 물리 SSD 장애 격리가 아니다.
6. OpenSSH server를 설치 옵션에서 활성화한다.
7. 일반 관리 사용자를 생성하고 root 직접 로그인은 사용하지 않는다.
8. hostname은 예를 들어 `seraph-service-01`로 지정한다. 실제 이름은 기록한다.

## 5. VM 네트워크

권장 첫 구성은 VM이 집 LAN에서 직접 IP를 받는 외부/브리지 네트워크다.

1. Hyper-V 가상 스위치 관리자에서 실제 연결된 유선 NIC를 선택해 외부 스위치를 만든다.
2. 호스트도 이 NIC를 공유하도록 설정한다. 스위치 변경 중 연결이 잠깐 끊길 수 있다.
3. VM NIC를 연결하고 Ubuntu에서 `ip -br address`, `ip route`로 확인한다.
4. 공유기에서 VM MAC 주소에 DHCP 예약을 설정한다.
5. DHCP 예약 대신 Ubuntu 고정 IP를 쓰려면 실제 NIC 이름·게이트웨이·DNS를 확인한 후 Netplan을 작성한다.
6. 원격으로 Netplan을 바꿀 때는 VM 콘솔을 열어두고 `sudo netplan try`로 복구 시간을 확보한다.

예시 IP를 그대로 넣지 않는다. 공유기의 DHCP 풀과 충돌하면 접속이 불규칙하게 끊긴다. Wi-Fi 브리지 동작이 불안정하면 유선 LAN을 우선 검토한다. NAT형 VM 네트워크를 선택하면 공유기와 Windows 양쪽 포트 전달이 필요할 수 있으므로 별도 기록한다.

## 6. Ubuntu 기본 설정

Ubuntu Bash:

```bash
sudo apt update
sudo apt upgrade
sudo apt install -y ca-certificates curl git openssh-server unzip jq
hostnamectl
timedatectl
ip -br address
ip route
systemctl status ssh --no-pager
```

서버 시간대는 UTC 또는 Asia/Seoul 중 하나로 정하고 로그 기록에 명시한다. 시간 동기화가 작동해야 TLS·CI 서명 문제가 줄어든다.

Windows에서 SSH 키 생성, 이미 키가 있다면 덮어쓰지 않는다:

```powershell
ssh-keygen -t ed25519
ssh <ADMIN_USER>@<SERVICE_VM_IP>
```

공개키만 Ubuntu의 관리 사용자 `~/.ssh/authorized_keys`에 등록한다. `.ssh` 권한 700, authorized_keys 600을 적용한다. 키 로그인이 새 터미널에서 성공한 뒤 비밀번호 SSH 로그인 정책을 강화한다. 변경 전 `sudo sshd -t`로 설정을 확인하고 기존 세션은 유지한다.

## 7. 전원과 자동 복구

- Windows 전원 설정에서 서버 사용 중 절전을 끈다. 노트북이라면 덮개 닫기 동작·발열을 확인한다.
- Windows 업데이트는 계획된 점검 시간에 재부팅한다. 보안 업데이트 자체를 영구 중지하지 않는다.
- Hyper-V의 VM 자동 시작을 설정하고, VM 자동 종료는 정상 종료 방식으로 정한다.
- 공유기와 PC 전원 복구 후 자동 부팅 여부는 BIOS 지원을 확인한다.
- VM 시작 지연을 설정해 디스크·네트워크 준비 시간을 둔다.
- 한 번 Windows를 재부팅하고 VM 자동 시작 → SSH → 서비스 상태 순서로 검증한다.

## 문제 해결

| 증상 | 확인 |
| --- | --- |
| VM 생성 실패 | 에디션·UEFI 가상화·메모리·디스크 |
| SSH timeout | VM IP 변경, NIC 연결, 게스트 방화벽, Windows 가상 스위치 |
| SSH refused | ssh 서비스·포트·설치 상태 |
| 재부팅 후 IP 변경 | 공유기 DHCP 예약 MAC 주소 |
| 빌드 중 호스트 멈춤 | RAM overcommit·디스크 용량·빌드 병렬도 |
