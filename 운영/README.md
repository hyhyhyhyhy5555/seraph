# 세라프 온프레미스 운영·출시 실습 안내

작성 기준: 2026-10-29. 이 폴더는 **실행 전 계획 및 운영 절차서**다. 문서 작성이 인프라 설치나 출시 완료를 의미하지 않는다.

## 확정한 목표

- LG 그램(Windows)은 배포·상시 서버 운영 전용이다. 개발·테스트·빌드는 보유 맥북에서 한다.
- Linux 가상머신(VM) 위에서 Kubernetes를 운영한다. 여기서 가상환경은 Python venv가 아니라 VM이다.
- API, PostgreSQL/pgvector, 소스 저장소, CI 러너, 컨테이너 저장소, AI 추론을 자체 운영한다.
- Android Google Play와 iOS App Store 양쪽 출시를 목표로 한다.
- 공유기 설정에 접근할 수 있다. 공인 IP·포트 개방 가능 여부는 아직 확인하지 않았다.
- 확인된 Windows 장비: i5-1240P, RAM 16GB, Iris Xe, 저장 공간 총 238GB 중 약 39GB 여유.
- MacBook에서 소스 작성·검사·서버 이미지 빌드·Android/iOS 빌드·스토어 제출을 진행한다. 지원 toolchain과 상세 사양은 확인 전이다.
- Windows 에디션·가상화 활성 상태, MacBook 상세 사양·Xcode, 도메인, 계정, 예산은 미정으로 남긴다.

진행 상태는 [세라프 TODO](../docs/agent/todo.md)에서 관리한다. 실행 증적과 환경 값은 [작업 기록표](12-작업기록과점검표.md)에 남긴다.

## 목표 구조

```text
MacBook: 개발·검사·서버 이미지(linux/amd64)·Android/iOS 빌드
        │ 서버 이미지·배포 선언 전달 (SSH 또는 자체 Registry)
        ▼
LG 그램 Windows → Ubuntu VM 1대 → K3s
                                 ├─ API
                                 ├─ PostgreSQL + pgvector + PVC
                                 ├─ 로컬 임베딩 서버
                                 └─ Ingress·TLS·모니터링
휴대폰 → HTTPS → 집 공유기 → 그램의 Ubuntu VM
자체 Git·Registry: 그램에서 서비스로 운영, 자원 실측 후 추가
별도 저장 장치: 암호화 백업
```

그램은 service VM 1대(4 vCPU·RAM 6GB 제안)로 API·DB부터 실행하며 저장 공간을 먼저 확보한다. 그램에 Android SDK·Xcode·npm 개발 환경이나 빌드용 VM을 준비하지 않는다.

## 두 장비의 역할: 사용자 확정

- **맥북:** 소스 편집, 로컬 개발용 DB, 테스트, 의존성 설치, 서버 이미지 빌드, Android/iOS 서명 빌드, 스토어 제출. 실제 도구 호환성은 설치 전에 확인한다.
- **그램:** 전달받은 이미지 pull/import, 배포 적용, migration Job 실행, API·DB·AI·Git·Registry 등 서비스 운영과 백업. 소스에서 npm/Gradle/container build는 하지 않는다.
- 흐름: MacBook 수정 → 검사 → 배포 대상 linux/amd64 이미지 생성 → Registry push 또는 파일 전송 → 그램 K3s 배포 → 실제 앱 검증.
- CI 빌드 runner는 맥북 측에서 구성한다. 그램에는 필요한 경우 배포 작업만 수행하는 제한된 runner를 둔다. 상세 runner 방식은 맥북 toolchain 확인 후 결정한다.
- 맥북을 닫아도 이미 배포된 그램의 서비스는 계속 동작한다. 맥북이 자는 동안 새 빌드는 대기할 수 있다.
- Intel i5 기반 그램 VM은 linux/amd64 대상이다. MacBook이 Apple Silicon이면 기본 arm64 이미지를 그대로 전달하지 않고 명시적으로 linux/amd64로 빌드한다.


## 자체 운영의 경계

자체 운영은 서버 실행·소스·빌드·이미지·AI를 직접 관리한다는 의미다. Apple/Google 스토어, 도메인 등록, 공용 DNS 위임, 공개 인증서 발급, OS/패키지/모델 최초 다운로드까지 외부 의존성이 전혀 없는 폐쇄망을 뜻하지 않는다. 자체 권한 DNS는 추가 실습으로 가능하지만 초기 필수 범위로 강제하지 않는다.

- GitHub Actions와 Expo EAS는 현재 준비된 자산이지만 최종 빌드 경로의 필수 서비스로 사용하지 않는다.
- 공식 스토어 제출에는 각 플랫폼 계정과 외부 연결이 필요하다.
- iOS 로컬 빌드는 Mac·Xcode가 필요하다. Windows Linux VM만으로 해결하지 않는다.
- 현재 RAG는 근거 검색 중심이다. 로컬 답변 생성 LLM 추가는 검색 완료 후 별도 확장이다.

## 명령어를 읽는 규칙

- `PowerShell`: Windows에서 실행. 관리자 권한이 필요한 경우 문서에 표기한다.
- `Bash / Ubuntu`: SSH로 들어간 Linux VM에서 실행한다.
- `macOS`: 확보한 Mac의 터미널 또는 Xcode에서 실행한다.
- `<...>`는 미정 값이다. 그대로 실행하지 않는다. `example.invalid`도 실제 도메인이 아니다.
- YAML은 구현 예시이며 아직 저장소에 실제 배포 파일로 추가되지 않았다.
- 먼저 실습 환경에서 검증한 후 운영에 적용한다. 운영 DB를 재초기화해 문제를 해결하지 않는다.
- 이미지·차트·설치 도구 버전은 실행 시 호환성을 검토하고 고정한다. 이 문서는 최신 버전을 자동 선택하는 스크립트가 아니다.

## 완료의 정의

실제 휴대폰 두 종류에서 스토어 설치한 앱이 개발 PC의 Metro 없이 HTTPS API에 연결되고, 코드 변경 배포·롤백·DB 복원·호스트 재부팅 복구를 재현할 수 있어야 한다. VM 여러 대가 같은 PC 위에 있어도 물리 호스트 장애를 견디는 고가용성은 아니다.
